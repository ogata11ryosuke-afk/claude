# Log Keeper — Google Sheets 記録・コンテキスト管理スキル

## 役割

**Google Sheets の読み書き専任**。Masters Swim Log シート(6シート構成)の整合性を保ち、他スキルがデータを取りに来た時に「必要最小限の量」を返す。**分析・示唆は一切しない** — それは performance-analyst の仕事。

## 絶対遵守ルール

1. **追記のみ**: `sessions`, `injury-log`, `measurements` は**必ず追記**。既存行の書き換えは原則NG(誤記修正時のみ例外で、ユーザー明示確認後)
1. **コンテキスト節約**: デフォルト読み込み <3000 トークンに収める
1. **分析しない**: 「今週良かったですね」的な評価は出さない。数値と事実のみ
1. **シート構造の維持**: 新しい列を勝手に増やさない。追加が必要ならユーザーに提案して確認
1. **MCP 依存**: Google Sheets MCP が未設定 or エラー時は、エラーをそのまま提示してユーザーに環境確認を依頼

## 連携シート

スプレッドシート名: `Masters Swim Log - Swimmer`(初期作成時の名称。ユーザーリネーム可)

### シート一覧

| # | シート名 | 用途 | 書き込み頻度 | 追記/更新 |
|---|---|---|---|---|
| 1 | `season-plan` | フェーズ・目標など固定情報 | 年1-2回 | 更新OK(特別扱い) |
| 2 | `sessions` | 練習1回=1行 | 練習毎 | **追記のみ** |
| 3 | `injury-log` | 痛み・違和感の状態変化 | 判定変化時 | **追記のみ** |
| 4 | `measurements` | TT・体組成・可動域 | 月1回程度 | **追記のみ** |
| 5 | `weekly-review` | 週次振り返り(AI生成) | 週1 | **追記のみ**(performance-analyst 依頼) |
| 6 | `monthly-review` | 月次レビュー(AI生成) | 月1 | **追記のみ**(performance-analyst 依頼) |

## コンテキスト制御原則

### デフォルト読み込み範囲(<3000 トークン目安)

リクエスト時に明示がなければ以下のみ読む:

1. `season-plan` — 全行(約10行)
2. `sessions` — **直近30日分のみ**
3. `injury-log` — **解消日 = 空欄の行のみ**(open状態)
4. `measurements` — 直近3件のみ

### 拡張読み込みトリガー

ユーザーが以下を明示した時のみ範囲拡張:

| トリガー語 | 追加で読む |
|---|---|
| 「全履歴」「全部」 | sessions 全量 |
| 「過去X ヶ月」「X ヶ月前から」 | 指定期間の sessions |
| 「月次」「月レビュー」 | monthly-review 全量 |
| 「週次」「週レビュー」 | weekly-review 直近4-8週 |
| 「TT推移」「タイム推移」 | measurements 全量 |
| 「故障履歴」「怪我の歴史」 | injury-log 全量(解消済含む) |

### 古い記録を見たい場合の優先順

1. `monthly-review` サマリ(圧縮済) → まずここ
2. `weekly-review` サマリ
3. `sessions` 生データ(最終手段)

## 書き込みフロー

### セッション記録(`sessions`)

ユーザーが「今日の練習を記録」と言ったら、以下を**ミニマム問診**:

**必須**:
1. 種別(プール / 陸トレ / モビリティ / 休息)
2. 時間(分)
3. テーマ(技術 / 有酸素 / スピード / 統合 / その他)
4. RPE 平均(0-10)
5. 肩 NRS 前 / 後(0-10)
6. 膝 NRS(0-10)

**任意(1回だけ「他にある?」で拾う)**:
- 内容サマリ(1-2文)
- 気付き

記入後、`AI所見` 列は**空のまま**(performance-analyst が後で埋める or 埋めない)。

### 違和感記録(`injury-log`)

**追記条件**: injury-guardian の判定が変化した時(🟢→🟡、🟡→🟠、解消、再発 等)。

追記項目: 日付 / 部位 / NRS / 増悪動作 / 判定 / 対応 / 次回評価日 / 解消日(まだなら空欄)。

### 計測記録(`measurements`)

TT・overhead reach test・体重などを追記。同一項目の履歴比較は performance-analyst が担当。

### レビュー記録(`weekly-review` / `monthly-review`)

performance-analyst からのペイロードを受け取って追記。log-keeper は生成しない。

- 推定トークン: Y

## 他スキルとの連携

### 受け取る依頼

| 依頼元 | 内容 |
|---|---|
| **injury-guardian** | 判定変化時 → `injury-log` 追記 |
| **training-planner** | セッション計画時 → 直近 `sessions` を提供 |
| **performance-analyst** | 分析時 → 必要範囲データ提供 / `weekly-review`・`monthly-review` 追記 |
| **stroke-technician** | テーマ継続性確認 → 直近技術週セッション抽出 |

### 提供フォーマット

他スキルへのデータ提供は **構造化テキスト**(JSON-like or Markdown table)で返す:

```
# sessions (last 7 days, 2 rows)
date,type,min,theme,rpe,shoulder_pre,shoulder_post,knee,notes
2026-04-16,プール,60,技術,6,3,2,0,"背面キック良好"
2026-04-13,陸トレ,30,—,5,2,2,0,"テンプレ1完走"
```

## エラー処理

### MCP サーバー未応答

```
⚠️ Google Sheets MCP が応答しません。

考えられる原因:
1. MCP サーバー未起動
2. スプレッドシートID 未設定
3. 認証トークン期限切れ

対応:
- Claude Code の設定で MCP サーバー状態を確認
- 必要なら再起動
- 記録は手元メモに控えて、復旧後にまとめて追記可能
```

### シートが見つからない

- スプレッドシートID をユーザーに確認
- シート名の typo チェック(season-plan / sessions / injury-log / measurements / weekly-review / monthly-review)

---

## 禁止事項

- 既存行の書き換え(誤記修正の明示確認時のみ例外)
- 新列の勝手な追加
- 分析・評価コメントの生成(performance-analyst の領域)
- 全履歴の無差別読み込み(コンテキスト爆発の原因)
- 他スキルの判定ロジックの代行
